## 二、dev 自动版本化 + 自动更新链路

### 背景
- 原 `updateUrl` 指向 GitHub `releases/latest`（HTML 页），SongLoft 更新检查按 JSON 解析 → **自动更新一直是坏的**。
- 原每次构建都用相同版本 `1.1.6-dev` → SongLoft 版本比较（字符串不等）认为「本地=远程」→ 永远无法发现新构建。
- 原 `download_url` 指向 `releases/latest/download/...`（解析到 main 稳定版）→ dev 包也下载不到。

### 已核实的宿主契约（songloft-org/songloft 服务端源码）
- `CheckUpdate`：GET `updateUrl` → `json.Unmarshal` 成 `{version, download_url}` → `HasUpdate = 远程 version != 本地 version`（**字符串不等**，非大小比较）。
- 版本格式：`semverRegexp = ^\d+\.\d+\.\d+`（前缀匹配）→ `1.1.6.04-dev` 合法。
- 安装/更新时 `updateUrl` 与 `download_url` 都会持久化到 DB；更新流程只读 `updateUrl` 返回的 `download_url`。

### 落地内容
1. **设计文档**：`docs/DEV_PLUGIN_AUTO_UPDATE_DESIGN.md`（plugin.json 管基础版本 + updateUrl；manifest.json 管实际版本 + 动态下载地址；CI 自动递增构建序号）。
2. **plugin.json**：`updateUrl` → `https://raw.githubusercontent.com/MbAIGC/songloft-plugin-iwebplayer-S/dev/manifest.json`；`download_url` 置空（不再存动态地址，避免过期）。提交 `09e335c`。
3. **`scripts/verify-build.mjs`**：`download_url` 校验 → **`updateUrl` 自动更新入口校验**（分支无关，main 亦适用），修复了因删 download_url 触发的 CI 红。提交 `57d648c`。
4. **调试 workflow** `Test-build-plugin-dev.yml` → **转正为正式 `build-plugin-dev.yml`**（提交 `ce8aa70`）：
   - push 触发（`src/static/plugin.json/package*/workflow`）+ 手动触发；
   - 版本自动递增：`1.1.6-dev` → `1.1.6.01/02/03...-dev`，**每次构建版本都保留**；
   - 序号从当前 dev pre-release 已有 zip 文件名解析最大值 +1（前缀过滤忽略旧版基础包）；
   - ZIP 内 `plugin.json` 用实际构建版本（构建前临时改、构建后恢复），发布前严格校验 zip 内版本=构建版本；
   - 发布到共享 pre-release `dev-1.1.6`（`concurrency: dev-release` 与 APK 串行）；
   - 成功后生成根级 `manifest.json`（`version` + 动态 `download_url`）并提交推送到 dev；`manifest.json` 不在触发路径 → 提交后不重触发防循环；
   - 全部步骤中文化。
5. **旧版退役**：原 `build-plugin-dev.yml` → **`build-plugin-dev-old.yml`**，触发置空（监听不存在的分支，永不触发），作为惰性备份保留。
6. **首个正式自动构建**：`.01`（用户测试）→ `.02`（`b19c17a`）→ `.03`（`2e5ad89`），manifest.json 随之自动更新；全链路（构建/校验/发布/提交 manifest）验证通过。

## 三、启动更新探测修复（APP_VERSION 写死导致误报）

### 问题
- `window.APP_VERSION = 'v1.1.6'` 在 `static/index.html` 中**写死**，从不反映真实插件版本（如 `1.1.6.03-dev`）。
- `checkLocalVersionUpdate()`（上游原始代码，`38c05c6` 引入）的版本守卫因此恒真、形同虚设；弹窗「检测到新版本…请手动刷新」实际只由**静态脚本 `?v=` 哈希对比**触发。自动更新生效后服务端真的换构建 → 用户当前/缓存页面哈希与服务端不一致 → **即使已是最新也误报**。

### 修复（提交 `2cc4c22`）
1. **构建注入真实版本**：`scripts/inject-version-hashes.mjs` 把 `plugin.json` 的实际版本注入 `window.APP_VERSION`（源文件改为 `__APP_VERSION__` 占位符；找不到占位符则构建失败）。应用内版本显示也随之正确。
2. **检查逻辑**：`checkLocalVersionUpdate` 改为**版本相同即视为已最新直接退出**（不再比较脚本哈希 → 缓存导致的假「新版本」不再触发刷新/弹窗）；仅当服务端版本号与当前页面不同才自动刷新一次。
3. **移除**「版本变化自动打开关于页」逻辑（用户不需要；旧实现也因写死从未生效）。

### 验证
- 本地：构建产物 `APP_VERSION = '1.1.6-dev'`，50/50 单测通过，verify 全绿。
- 线上自动构建 `.03-dev`：下载发布产物实测 `window.APP_VERSION = '1.1.6.03-dev'`，manifest.json 已更新至 `1.1.6.03-dev`。
