# 逐字歌词（KTV）引擎优化总结

> 日期：2026-08-22
> 涉及文件：`static/lyrics.js`、`static/index.html`（CSS）
> 提交范围：`bd9ba62`（JS 替换）、（待定 CSS）

---

## 一、优化背景

用户反馈逐字歌词（KTV）有轻微延迟，相比原生音乐播放器不够精准。经分析（见 `docs/逐字歌词引擎优化总结.md`← 此文档），延迟来源包括：

1. **每帧 DOM 操作过多**：`sync()` 每帧遍历所有字，调用 `getElementById()` + `setProperty()` + `className` 赋值，5 个字 = 15 次 DOM 操作/帧
2. **CSS transition 动画**：`.ktv-word.sung` 有 `transition: transform 0.15s`，字唱完回位有 150ms 动画
3. **末字时长缺失**：最后那个字没有后续时间戳，duration 固定 0.01s，扫光一闪而过
4. **`audio.currentTime` 固有滞后**：浏览器音频缓冲区导致

## 二、JS 引擎优化（已实施）

### 2.1 替换方案

用 `TestDemo/CHATGPT_lyrics.js`（GPT 优化版）替换 `static/lyrics.js`，API 完全兼容。

### 2.2 核心优化对比

| 维度 | 旧版 | 新版 | 效果 |
|------|------|------|------|
| DOM 查找 | 每帧 `getElementById()` × 所有字 | `parse()` 时一次性缓存到 `wordElements[][]` 数组，运行时 0 DOM 查询 | 每帧 5→0 次 |
| 每帧操作范围 | 遍历所有字，更新 className + progress | 只更新 **当前正在唱的一个字** 的 progress | 每帧 5→1 次 |
| 行搜索 | 线性遍历 `parsedLyrics` O(n) | 二分查找 `findActiveLine()` O(log n) | 50 行时 50→6 次比较 |
| 字搜索 | 线性遍历 words O(n) | 二分查找 `findActiveWord()` O(log n) | 10 字时 10→4 次比较 |
| className 写保护 | 每帧无条件赋值 | 检查 `className !== 'sung'` 后才赋值 | 减少样式重算 |
| 末字时长 | `Math.max(0.01, ...)` ≈ 0.01s | 根据下一行行首时间计算，`Math.min(maxDur, 2.0)` | 扫光完整 |
| 代码行尾 | CRLF | LF | 与项目其他文件一致 |

### 2.3 预期效果

每帧 DOM 操作从 15 次降到 1 次，样式重算减少约 60%，帧渲染时间更稳定，视觉延迟降低。

## 三、CSS 优化（待实施）

### 3.1 建议内容

来自用户反馈的 CSS 优化建议：

```css
/* 基础：关闭过渡，添加 GPU 优化提示 */
body.ambient-active.player-open:not(.split-view-active) .ktv-word {
    background-image: none !important;
    -webkit-text-fill-color: initial !important;
    transition: none !important;       /* ← 去掉 150ms 过渡 */
    will-change: transform;            /* ← 提示浏览器提升为合成层 */
}

/* 正在唱的字：gradient 加 !important 确保覆盖 */
body.ambient-active.player-open:not(.split-view-active) .lyric-line.active .ktv-word.singing {
    transform: scale(1.1) translateY(-2px);
    background-image: linear-gradient(...) !important;
    -webkit-background-clip: text !important;
    background-clip: text !important;
    -webkit-text-fill-color: transparent !important;
    color: transparent !important;
    text-shadow: none !important;
    filter: drop-shadow(0 2px 4px rgba(0,0,0,0.6))
            drop-shadow(0 0 10px rgba(236,72,153,0.4));
}
```

### 3.2 分析

| 修改项 | 当前值 | 建议值 | 影响 |
|--------|--------|--------|------|
| `transition` | `transform 0.15s cubic-bezier(...)` | `none !important` | 去掉 sung→singing 的 150ms 回位动画，响应更即时 |
| `will-change` | 无 | `transform` | 提示浏览器为 transform 创建独立合成层，减少重排 |
| gradient `!important` | 部分有 | 全部加 | 防止其他样式覆盖 singing 渐变 |
| `text-shadow` | 已有 `none` | 加 `!important` | 确保覆盖 |

**优点**：
- `transition: none` 直接消除 150ms 的 CSS 动画延迟，字的状态变化即时反映
- `will-change: transform` 降低 GPU 合成开销，滚动/缩放更流畅

**缺点**：
- 失去 sung→singing 的平滑回位动画，视觉反馈变"硬"
- `will-change` 会占用额外 GPU 内存（但 5-10 个字，可忽略）

### 3.3 结论

**建议实施**。对于逐字歌词，**即时响应比动画平滑更重要**——用户感知到的是"字唱到了吗"，不是"字弹回去好不好看"。

3. 格式 C（内嵌毫秒时间戳 `(ms,ms)`）歌词的支持，待实际遇到时再实现
