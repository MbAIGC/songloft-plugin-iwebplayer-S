# GPT-iWP-S-1.3.5.48 审阅结果

审阅日期：2026-09-19

## 结论摘要

当前最大的风险不是单个 CSS 值，而是播放状态、分栏状态与全屏状态叠加后缺少统一状态机与浏览器级回归测试。现有 Vitest（50/50 通过）、JavaScript 语法检查与断点规则审计均通过，但不足以验证真实浏览器中的状态切换与布局重排。

## P0：全屏/窄窗口状态组合存在工具栏漏显风险

工具栏显示规则存在方向相互冲突的可能：

- `body.split-view-active .toolbar-split-only { display: flex; }`
- 宽屏沉浸态只隐藏了 `.toolbar-wrapper`、`.toolbar-main-box`、`#online-toolbar-container`
- 存在多个针对 `ambient-active.split-view-active` 的局部补丁

因此，若播放器全屏时仍保留 `split-view-active`，`#toolbar-split` 可能仍由全局规则显示；当前隐藏工具栏的规则没有完整覆盖该节点。

建议明确沉浸播放时工具栏的产品规则。若沉浸态应完全隐藏工具栏，应使用一条完整的收口规则，同时覆盖普通工具栏与 `#toolbar-split`，避免仅隐藏部分节点。

## P0：从全屏回到小窗口后不切回手机布局

CSS 媒体查询会随窗口宽度变化，但 `split-view-active` 是 JavaScript 写入的状态类。若退出全屏或窗口尺寸变化后没有重新计算并移除该类，页面仍会套用分栏规则，表现即为“小窗口内容不会自动恢复手机界面”。

需要统一审查并收敛以下触发入口：

- `resize`
- `orientationchange`
- `fullscreenchange`
- 进入或退出播放器沉浸态
- 初始加载与恢复页面状态

建议收敛到单一、幂等的 `syncResponsiveLayoutState()`，集中决定 `split-view-active` 的增删；不要让多个事件处理器分别修改该状态。

## P1：性能风险集中在沉浸背景的多层合成

手机沉浸态同时使用了：

- 全屏封面背景图与 `transform: scale(1.05)`
- 背景透明度叠加与覆盖层
- `.full-player`、`.player-bar` 两块大面积 `backdrop-filter: blur(20px)`
- 多处高优先级 `!important` 规则与状态切换

移动端上，两个大面积模糊层叠加全屏背景会显著增加合成与重绘成本，可能造成切歌、展开/收起播放器、滚动时掉帧。

建议：

1. 模糊效果限制为单层，优先保留播放器主体，移除底栏或背景的重复模糊。
2. 切歌期间暂时降低背景效果，例如禁用 blur；封面稳定后再恢复。
3. 不对大面积容器使用 `transition: all`，只对实际需要动画的属性设定 transition。

## P1：Header 存在先设置后撤销的级联债务

当前先对沉浸 Header 设定实色背景：

```css
body.ambient-active.player-open .header {
  background: var(--top-color, var(--bg-color)) !important;
}
```

随后又用更具体的手机规则将其改为透明：

```css
body.ambient-active.player-open:not(.split-view-active) .header {
  background: transparent !important;
}
```

功能上可以工作，但会提高维护难度，也容易在新状态组合中遗漏覆盖分支。

建议将手机沉浸态与分栏沉浸态定义为互斥规则，避免同一属性在相邻规则中反复反转。

## P1：分栏规则重复维护，规则成对不等于实际正确

此前审计确认 768–959 与 >=960 的关键规则成对存在、主要层级一致；但同一组件仍在多处媒体查询和补丁中重复定义，包括：

- `header`
- `player-bar`
- `full-player`
- `playlist`
- 工具栏与下拉层级
- 氛围背景层

这类重复最容易遗漏某个状态组合。建议逐步提取共用选择器和 CSS 变量，仅在断点中保留确实不同的尺寸或布局差异。

## P2：自动化覆盖不足

当前已验证：

- Vitest：50/50 通过
- `static/*.js` 语法检查通过
- 断点规则审计通过

但没有覆盖：

- 浏览器 `fullscreenchange`
- 调整窗口宽度后 `body.classList` 是否同步
- 工具栏节点在各状态下的真实可见性
- 播放器开关与分栏状态组合
- 移动端渲染性能、长任务和掉帧

建议至少新增四条浏览器级回归测试：

1. 宽屏打开播放器后缩至手机宽度：必须移除 `split-view-active`。
2. 手机宽度打开播放器：所有非沉浸工具栏必须隐藏。
3. 进入与退出全屏：布局状态与工具栏状态必须同步。
4. 切歌、展开播放器、拖动进度条：验证无明显长任务或掉帧。

## P2：工作区卫生

检查发现多个 JavaScript 文件存在大量尾随空白。它们不太可能是本次 UI 故障根因，但会干扰 diff 审阅并扩大修改面。建议单独以纯格式化提交清理，勿与功能修复混合。

## 已确认的 1.3.5.48 状态

`1.3.5.48` 的核心 UI 修改仅涉及手机沉浸播放页 Header：从封面顶部取色改为透明，以消除顶部色带接缝。该修改没有直接更改工具栏或分栏切换逻辑。

## 推荐修复顺序

1. 审查并统一 `split-view-active` 的状态更新入口，优先修复全屏退出或缩窗后不恢复手机布局的问题。
2. 收口沉浸播放期间所有工具栏的可见性规则，覆盖普通工具栏与 `#toolbar-split`。
3. 整理 Header 的级联覆盖链，拆分手机和分栏沉浸态的互斥样式。
4. 降低大面积 blur 与背景合成开销。
5. 增加浏览器级回归测试，再处理其余零散视觉异常。
