# 版本号自动化方案

> 状态：**待实施** ⏳
> 提出日期：2026-08-22
> 涉及文件：`scripts/auto-version.mjs`（已创建）、`.github/workflows/build-plugin.yml`（待修改）

---

## 现状问题

每次发布新版本需要手动修改三处：

1. `plugin.json` 中的 `"version"` 字段
2. `package.json` 中的 `"version"` 字段
3. `DEV_RELEASE_NOTES.md` 中的标题版本号

手动操作容易遗漏或不一致。

## 方案设计

### 核心思路

`plugin.json` 只维护 **base 版本**（如 `1.1.6-dev`），patch 和 build 号从 git 元数据自动生成。

```
plugin.json 中的 base 版本  (仅 major.minor 变化时手动改)
     +
-dev.总提交数+短提交哈希    (git rev-list --count HEAD 自动计算)
     ↓
完整版本: 1.1.6-dev.159+896565f
```

### 实现方式

`scripts/auto-version.mjs` 脚本已创建，提供三种输出模式：

| 命令 | 输出示例 | 用途 |
|------|----------|------|
| `node scripts/auto-version.mjs` | `1.1.6-dev.159+896565f` | 插件 zip 文件名、构建产物标识 |
| `node scripts/auto-version.mjs --base` | `1.1.6` | GitHub Release tag（`dev-1.1.6`） |
| `node scripts/auto-version.mjs --tag` | `dev-1.1.6` | 直接用于 `gh release` |

`package.json` 中已添加 `npm run version` 快捷命令，可直接查看当前自动版本号。

### 集成示例（CI 工作流修改）

```yaml
# 原来（手动读 plugin.json）
PLUGIN_VERSION=$(python3 -c "import json;print(json.load(open('plugin.json'))['version'])")
DEV_RELEASE_VERSION="${PLUGIN_VERSION%-dev}"
DEV_TAG="dev-${DEV_RELEASE_VERSION}"

# 改为（自动计算）
PLUGIN_VERSION=$(node scripts/auto-version.mjs)
DEV_RELEASE_VERSION=$(node scripts/auto-version.mjs --base)
DEV_TAG=$(node scripts/auto-version.mjs --tag)
```

### 优点

- 每次构建自动生成唯一、递增的版本号，无需手动修改
- 版本号包含 commit 计数和短哈希，可追溯
- 符合 semver build metadata 规范（`-dev.159+896565f`）
- 零侵入：脚本在 `scripts/` 下，不影响现有逻辑

### 注意事项

- `main` 分支稳定发布仍使用 `plugin.json` 精确版本号，不改动
- `plugin.json` 的 `version` 字段在 major.minor 版本迭代时仍需手动更新一次（如 `1.1.6-dev` → `1.2.0-dev`）
