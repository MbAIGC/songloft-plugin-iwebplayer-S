# 分栏（宽屏）模式三栏工具栏改造总结

> 对应提交区间：`c712f20`（首版） → `e236eea`（暗色模式收尾）

## 一、需求

1. **宽屏（分栏 `split-view`）模式下**，把顶部工具栏改造成三栏结构：
   - **左栏**：在线资源搜索（搜歌 / 搜单 + 音源 / 平台切换），默认 32%，聚焦展开到 48%。
   - **中栏**：本地曲库搜索，36%，点击后自动进入「曲库搜索」模式
   - **右栏**：歌单选择下拉（含「在线资源 / 曲库搜索 / 我的歌单」）+ 列表操作菜单，32%（聚焦展开时保持 32% 不变）
2. **手机端显示完全不做任何调整**，恢复原有工具栏，两套结构互不影响。
3. **「所有歌曲」按添加时间倒序排列**（最新添加的排最前）。
4. **能复用现有函数名的地方不引入新函数**，保持 `player.js`、`online.js`、`playlist.js` 既有逻辑不变。
5. 由用户确认后再提交 GitHub，主流程构建只跑 `main` 分支。

## 二、设计思路

### 2.1 分栏模式的入口

沿用已有的 `split-view-active` class（`<768px` 移除、`>=768px` 根据 `localStorage['iwebplayer-s.split_mode']` 添加），所有分栏样式以 `body.split-view-active` 为前缀。

### 2.2 复用真实 DOM 元素，而不是做代理

用户明确否决过“代理按钮触发搜索”的方案，要求**把真实的 `#playlist-container` 等元素直接放进右栏**。因此：

- 新增 `.toolbar-split-only` 三栏外壳，HTML 结构（`static/index.html`）：

  ```
  #toolbar-split
    └─ .toolbar-split-inner（卡片外壳，overflow: visible）
        ├─ #tbs-online    左栏：自定义输入框 + 搜歌/搜单 + 引擎/音源下拉容器
        ├─ #tbs-library   中栏：`#search-inline-wrap` 由 JS 移入
        └─ #tbs-playlist  右栏：`#playlist-container` + `#menu-dropzone-row1` 由 JS 移入
  ```

- **共享控件移动**：`MutationObserver` 监听 `body.classList` 中 `split-view-active` 变化，调用 `moveToolbarControls(isSplit)` 把以下控件在手机工具栏与三栏之间搬移：
  - `#playlist-container`、`#menu-dropzone-row1` → `#tbs-playlist`
  - `#search-inline-wrap` → `#tbs-library`
  - `#engine-container`、`#mf-plugin-container` → `#tbs-online`

  搬移元素不会丢事件监听，原有功能（下拉、搜索、音源切换）天然保留。

- **左栏在线搜索**：左栏自定义输入框 `#tbs-lx-input` 把输入实时转发到原始 `#lx-search-input`（dispatch input 事件），点击「搜歌/搜单」时写入原始输入框并调用原始 `doOnlineSearch / doLxPlaylistSearch`（经 `tbsDoLxSearch` 封装）。`mousedown` 拦截 + `relatedTarget` 判断保证点击内部按钮/下拉时左栏不收起。

- **CSS 变量控制列宽**：`--tbs-online-w` / `--tbs-lib-w` / `--tbs-pl-w` 驱动三栏宽度；`.tbs-online.expanded` / `.tbs-library.expanded` 通过 `tbsExpandOnline` / `tbsExpandLibrary` 切换展开态，并让该栏 `overflow: visible` 以放下拉。

### 2.3 排序

`static/playlist.js` 首次同步写入歌曲时记录 `_addedAt = Date.now()`，对 `syncReconstructed['所有歌曲']` 按 `(b._addedAt || 0) - (a._addedAt || 0)` 倒序排序；同时 `uniqueBaseNames.add('曲库搜索')` 保证「曲库搜索」始终出现在歌单下拉里。

### 2.4 构建约束

`.github/workflows/build-plugin.yml` 分支限定为 `[main]`，`build-apk.yml` 保持 main-only，避免 dev 分支每次合并都触发产物构建。

## 三、遇到的问题与解决方案

| # | 问题 | 根因 | 解决方案 |
|---|------|------|----------|
| 1 | 手机端工具栏被破坏 / 显示异常 | 最初把原工具栏整体替换为分栏结构，`.toolbar-split-only{display:none}` 放在 `@media` 内部才生效，顺序混乱 | 恢复原始 `toolbar-main-box` 结构；`.toolbar-split-only` 移到全局 CSS；分栏只在 `split-view-active` 时显示，手机端完全不动原工具栏 |
| 2 | 手机工具栏未随分栏切换隐藏（非氛围模式时仍显示） | 原有隐藏规则以 `body.ambient-active.split-view-active` 为前提，关闭氛围背景时失效 | 增加非氛围兜底：`body.split-view-active .toolbar-main-box{display:none!important}`（氛围与非氛围都隐藏） |
| 3 | 歌单下拉被裁剪、点不出来 | 分栏容器 `overflow: hidden` | `.toolbar-split-inner`、`.tbs-playlist` 设 `overflow: visible` |
| 4 | 歌单下拉定位错乱、溢出到主内容区 | `.tbs-playlist` 被 `body.split-view-active .tbs-playlist{position:static}` 覆盖，`#playlist-opts` 找不到定位祖先，锚到 50% 宽的 `#playlist-row` 上 | 分栏下强制 `.tbs-playlist{position:relative!important}`，并右对齐、`min-width:260px`，恢复原下拉观感 |
| 5 | 点击「曲库搜索」后列表不刷新 | `performLocalSearch` 只在 `currentPlaylist === '曲库搜索'` 时重新渲染 | 聚焦/回车时先 `switchPlaylistSilently('曲库搜索')` 再搜索；下拉选中项走原 `createOpt` 逻辑 |
| 6 | 搜歌/搜单/音源/平台四个按钮无效，点击后左栏收起 | 点击这些元素时 `#tbs-lx-input` 失焦触发 `tbsReset()`，左栏 collapse，按钮被裁剪吞掉点击 | 左栏内部 `mousedown` 对非输入框 `preventDefault()`（保持输入框焦点）；`blur` 里用 `e.relatedTarget` 判断焦点是否仍落在 `#tbs-online` 内，是则不收起 |
| 7 | 音源/平台下拉被裁剪 | `.tbs` 默认 `overflow: hidden` | 展开态 `.tbs-online.expanded{overflow:visible}` |
| 8 | 搜歌/搜单在非「在线资源」歌单下无结果 | 搜索结果只在「在线资源」主内容区渲染 | `tbsDoLxSearch` 先 `switchPlaylistSilently('在线资源')` 再触发搜索；空关键词 toast 提示 |
| 9 | 中栏曲库搜索在右侧非「曲库搜索」歌单时无效、回车无效 | focus 处理器有「在线资源」排除项导致不切换；`#search-input` 原本没有回车监听 | 聚焦中栏无条件切「曲库搜索」模式；新增 Enter 监听：确保模式后执行 `performLocalSearch` |
| 10 | 中栏提示文字与图标不符合预期 | 占位文字复用手机端 | 分栏下占位文字改为「本地曲库搜索」，手机端恢复「请输入关键字...」；中栏输入框左侧增加放大镜图标（`.search-inline-icon` 默认隐藏，仅分栏显示） |
| 11 | 底部出现横向滚动条 | 分栏内容/宽度撑破容器 | `body.split-view-active{overflow-x:hidden}`；`.toolbar-split-inner`、`.tbs` 增加 `min-width:0` 防止 flex 子项撑宽 |
| 12 | 暗色模式下工具栏背后有半透明方框 | 三栏工具栏外壳用纯色 `var(--card-bg)`，与氛围背景的其他半透明磨砂卡片不统一；暗色模式下 `rgba(255,255,255,0.15)` 边框 + `rgba(0,0,0,0.4)` 投影形成明显方框，`playlist-row` 还有重投影 | 把 `.toolbar-split-inner` 纳入氛围卡片处理（亮色/系统暗色/手动暗色）；暗色下边框改 `rgba(255,255,255,0.06)`、投影改 `0 2px 12px rgba(0,0,0,0.12)`；暗色分栏 `playlist-row` 去投影，整体与浅色观感一致 |
| 13 | 排序无效 | 之前排序未落到实际渲染数组 | 在 `syncReconstructed['所有歌曲']` 上补 `sort`（按 `_addedAt` 倒序） |
| 14 | TestDemo/ 目录被误提交 | 本地测试目录没加忽略 | `git rm --cached` + `.gitignore` |

## 四、涉及文件

- `static/index.html` — 三栏工具栏的 HTML / CSS / JS（主要改动）
- `static/playlist.js` — `_addedAt` 记录、`所有歌曲` 倒序排序、`曲库搜索` 恒在歌单下拉
- `.github/workflows/build-plugin.yml` — 分支限定 `[main]`
- `static/player.js` / `static/online.js` — **未修改**（满足复用约束）

## 五、后续注意

- 分栏下所有定位类的下拉（歌单、音源、平台、列表菜单）依赖 `.tbs-playlist` / `.tbs-online.expanded` 的 `overflow: visible` 与定位祖先，后续改动不要重新加 `overflow: hidden`。
- 手机端与分栏共用同一批真实 DOM 元素（通过 `moveToolbarControls` 搬移），任何「代理元素」思路都会导致原有交互丢失。

## 三、后续改造：三栏 → 两栏 + 设备选择器并入（2026-09-18）

原三栏中「在线资源搜索」与「本地曲库搜索」是两个独立输入框，加上 header 右侧单独占位的设备选择器，宽屏顶部显得冗余。经确认后做了如下合并（**手机端仍然完全不变**）：

### 3.1 搜索合并：一个输入框 + 本地/在线来源开关

| 项目 | 改造前 | 改造后 |
| --- | --- | --- |
| 输入框 | `#tbs-lx-input`（在线，左栏 32%）+ `#search-input`（本地，中栏 36%） | 两个输入框移入**同一栏**，由开关切换显示，同一时刻只显示一个 |
| 来源切换 | 无（靠输入框位置区分） | `#tbs-src-toggle` 的「本地 / 在线」二段开关 |
| 模式记忆 | — | `localStorage['iwebplayer-s.wide_search_mode']`；无记录时**跟随当前歌单**（在「在线资源」里默认在线，其它默认本地） |
| 栏宽 | `32% / 36% / 32%`，聚焦时跳 `48/20/32` | 搜索栏 `flex: 1` 自适应，不再有栏宽跳动（`tbsExpand*` 的宽度变量被 CSS 覆盖） |

实现要点：

- **不改搜索逻辑本身**：本地仍走 `performLocalSearch()`，在线仍走 `tbsDoLxSearch()`（写 `#lx-search-input` + 点搜歌/搜单），只是"同一时刻只显示一个输入框" —— 因此两种搜索的既有行为、关键词记忆（`iwebplayer-s.local_search_keyword`）都原样保留。
- 模式类挂在 `.tbs-online` 上（`mode-local` / `mode-online`），CSS 负责显隐：本地模式隐藏在线输入框与其图标/清除/搜歌搜单/引擎插件；在线模式隐藏本地输入框并常显引擎与插件选择。
- 聚焦任一输入框会同步开关状态（避免开关与实际焦点不一致）。

### 3.2 设备选择器并入同一行

- `#device-container`（本机 / 小爱音箱）由 `moveToolbarControls()` 在宽屏时移入工具栏最右的 `#tbs-device` 槽位，窄屏时移回 `.header-controls`；
- 宽屏下 `.header-controls` 置空后 `display: none`，header 只剩品牌与设置入口，不再出现"设备按钮孤零零挂在右上角"的观感。

### 3.3 宽屏最终形态

```
[本地 | 在线] [🔍 输入框 .............] [搜歌 搜单] [引擎] | [歌单/所有歌曲 ▾] | [本机 ▾]
└──────────────── 搜索栏（flex:1）────────────────┘   └─ 30% ─┘        设备
```

### 3.4 遗留 / 未做

- **WebDAV 引擎缺口**（改造前就存在）：宽屏在线搜索只驱动 `#lx-search-input` + `#lx-search-btn`，没有网盘分支，而宽屏下真正的输入行 `#online-toolbar-container`（含 `#wd-search-row`）是 `display:none` —— 当前引擎为网盘时，这个搜索框很可能搜不出结果，建议在网盘模式下单独验证并补齐路由。
- 窄屏（<768）仍是"在线工具栏独立一行 + 曲库搜索框"的原结构，未做合并。

### 3.5 修正（同日回修）

用户验收后回修三点：

1. **工具栏位置**：由"header 一行 + 工具栏第二行"改为**整体并入 header 行**（即原来「本机 / 小爱音箱」所在的那一行）。做法：宽屏时 `#toolbar-split` 由 JS 搬进 `.header`（紧随 `.header-left-group`），原第二行 `#playlist-row` 在宽屏下 `display:none`；窄屏时工具栏按记录的原父节点/兄弟节点还原。
   - 连带调整：右栏列表顶部偏移 `--split-list-top` 由 `115px`（header 56 + 工具栏 ~59）改为 `58px`，列表因此多出约 59px 高度。
2. **字号还原**：不再用缩小字号换空间 —— 去掉设备选择器、引擎/插件下拉的 `font-size: 12px` 覆盖，本地/在线输入框统一为 `14px`；空间不足时由 `flex: 1` 的搜索框自行收窄。
3. **修复下拉菜单消失**（本次改造引入的回归）：`.tbs` 基础样式带 `overflow: hidden`，设备选择器移入后下拉被裁剪。已给 `.tbs-device` 与 `.tbs-online.mode-online` 加 `overflow: visible; position: relative;`（在线模式的引擎/插件下拉同样受益）。

### 3.6 二次修正（同日）

1. **工具栏越过中界线**：并入 header 后工具栏从 logo 右侧一直铺到窗口右边，压到了左半栏。改为 `body.split-view-active .header-left-group { flex: 0 0 50% }` —— header 左半（品牌/设置）固定占 50%，工具栏只占右半栏（与中界线留 12px），与下方左右分栏的边界对齐。
2. **搜索框默认点不进去（无法输入）**：`#tbs-online` 上原有的"防止点击按钮/下拉夺走输入框焦点"逻辑写的是 `if (e.target !== tbsLxInput && ...) e.preventDefault();`，只放行了**在线**输入框。合并后**本地**搜索框也在这条栏里，它的 mousedown 同样被 `preventDefault()`，于是点不进去；只有点「本地 / 在线」开关时靠 JS 的 `.focus()` 才能激活 —— 与用户观察到的现象一致。已改为 `if (e.target.closest('input, textarea')) return;`：任何输入框都放行，按钮/下拉仍保持不夺焦。

### 3.7 拥挤与遮挡优化（同日，① + ② + ③）

用户在"全屏勉强、半宽屏遮挡"后确认按组合方案优化。

**原因量化**（右半栏可用宽度，在线模式下的常驻控件）：

| 控件 | 宽度 | 可收缩 |
| --- | --- | --- |
| 本地/在线开关 | ≈76px | 否 |
| 搜歌 / 搜单 | ≈80px | 否 |
| 引擎 `#engine-val` | ≈80px | 否（`flex: 0 0 auto`） |
| 插件 `#mf-plugin-val` | ≈70–100px | 半 |
| 歌单栏 `.tbs-playlist` | 死 30% | **否（`flex: 0 0 auto`）** |
| 设备 `#device-val` | ≈70–95px | 否 |

固定项合计 ≈433px + 歌单栏 30%：1280px 窗口下输入框只剩约 15px（拥挤）；960px 窗口下需求 577px > 可用 480px → 搜索栏内容溢出。而歌单栏不可收缩，被挤的只有搜索栏，其溢出内容因 `.tbs-online.mode-online{overflow:visible}` 直接可见 → **盖住「所有歌曲」**。

**① 消除遮挡**

- 歌单栏改为可收缩：`flex: 0 1 auto; width: auto; min-width: 132px; max-width: 240px`；
- `.tbs-online` 默认保持 `overflow: hidden`（不遮挡邻居），只有浮层展开时才放开。

**② 去掉常驻负担：音源 / 平台改为浮层**

- 在线栏新增「音源 ▾」按钮（`#tbs-engine-btn`，本地模式隐藏）；
- 引擎 / 插件选择器不再常驻，点击后在按钮下方以浮层（`position: absolute`，z-index 330）展开，点外部或切到本地模式自动收起；
- 常驻宽度因此减少约 160px。

**③ 按宽度分级：窄了自动回两行**

- 新增阈值 `WIDE_TOOLBAR_INLINE_MIN = 1100`：`isSplit && innerWidth >= 1100` 时给 `body` 加 `wide-toolbar-inline`，工具栏与 header 同行、`#playlist-row` 隐藏、`--split-list-top: 58px`；
- 低于阈值（含 768–1099 的半宽屏）工具栏回到 `#playlist-row` 第二行，`--split-list-top` 回到 `115px` → 半宽屏不再拥挤、不会遮挡；
- `resize` 事件（150ms 防抖）会重新判定，跨过阈值时在两种布局间自动切换；
- 注意：`classList.toggle` 只在实际变化时改动 DOM，不会与 `MutationObserver` 形成循环。

### 3.8 音源浮层与细节打磨（同日）

用户验收 3.7 后提出 4 点，已全部落实：

1. **「音源 ▾」与「搜歌 / 搜单」文字不齐**：三者统一盒模型 `.tbs-lx-actions .tbs-lx-btn { display: inline-flex; align-items: center; justify-content: center; height: 22px; line-height: 1; }`（原先靠 padding 撑高，含 `▾` 的按钮盒高不同导致基线错位）。
2. **音源浮层里补回 WebDAV 搜索**：浮层底部新增一行代理输入 `#tbs-wd-input`（放大镜 + 输入框 + 清除），与上方芯片用 `.tbs-src-sep` 横线分隔。
   - 聚焦该行会**自动切到 WebDAV 引擎**（否则输入会打到当前引擎上）；
   - 输入时把值镜像进原有 `#wd-search-input` 并派发 `input` 事件 → **完全复用原有的「输入即搜」逻辑**（WebDAV 引擎的 `searchSong` 在内存曲库里按文件夹名 + 歌曲名匹配）；
   - 之所以用代理而不是搬 `#wd-search-row`：`refreshOnlineUI()` 会把全局菜单按钮移进 `#menu-dropzone-wd`，搬走整行会让菜单按钮被困在浮层里。
3. **音源不需要三级菜单，改成二级**：原先要「点音源 → 点引擎下拉 → 点平台/服务器下拉」三级；现在浮层内直接把 `#engine-opts`（LXMusic / WebDAV）与 `#mf-plugin-opts`（平台 / 服务器）**渲染成两组芯片并排显示**（CSS 覆盖 `.select-options` 的绝对定位与 `.select-value` 的触发器），点一下即选中 —— 浮层 → 芯片 = 二级。既有的事件处理（引擎切换是委托在 document 上、平台是直接绑定）**全部保持原状**，因此引擎切换的状态备份/恢复、平台排序等逻辑不受影响。
4. **在线搜索提示词随引擎变化**：`#tbs-lx-input` 的 placeholder 由 `updateWideOnlinePlaceholder()` 统一维护 —— `LX-Music 在线资源搜索` / `WebDAV 资源搜索`，在模式切换与引擎切换后都会刷新。
5. **设备（本机 / 小爱音箱）文字与旁边一致**：原先继承 `.select-value` 的 15px/36px 规格偏大，现改为与引擎/歌单相同的 13px + flex 垂直居中 + 统一内边距。

### 3.9 音源浮层切换 bug 修复（同日）

用户反馈：浮层两行贴太近；LXMusic ↔ WebDAV 切换时「搜索框、提示词、再次点音源」都有问题。

**根因**：引擎切换由 `online.js` 的委托处理，它会把关键词写回**各自的原生输入框**：

```js
document.getElementById('wd-search-input').value = (oState.view === 'dav_search' || oState.view === 'song') ? (oState.keyword || '') : '';
document.getElementById('lx-search-input').value = oState.keyword || '';
```

而工具栏用的是**代理输入框**（`#tbs-lx-input` / `#tbs-wd-input`），没人同步它们 → 切了引擎后搜索框仍显示旧引擎的词（或空白）；提示词只在点击芯片时用 `setTimeout` 刷一次，任何其它路径的切换（返回按钮、`restoreOnlineView` 等）都不会刷新；再次点开音源时，浮层里的两个选择器若被其它搬移逻辑挪走，就会看到空浮层。

**修复**：

1. **两行垂直距离**：`.tbs-src-group > * + * { margin-top: 10px }`，分隔线外边距 `8px` → `12px 0 10px`；
2. **搜索框同步**：新增 `syncWideSearchInputsFromEngine()`，从当前引擎对应的原生输入框把关键词同步到代理输入框（并刷新提示词）；
3. **最稳的挂钩点**：包装 `window.refreshOnlineUI`（online.js 在**任何**引擎 / 视图切换后都会调用它），包装里统一做"同步 + 提示词刷新"，因此返回按钮、`restoreOnlineView` 等路径也一并覆盖（用 `__wideOnlineUIHooked` 防重复包装）；
4. **浮层自愈**：新增 `ensureSourcePopoverContent()`，每次展开音源时确认引擎 / 平台两个选择器确实在浮层内（不在则重新挂回），并在展开时先同步一次内容；
5. 展开态下的"点外部关闭"判断补上 `#tbs-src-popover`，避免点击浮层内部被误判为外部。

### 3.10 浮层芯片不显示 + 宽屏全局菜单丢失（同日）

**① 直接点「音源」看不到任何芯片，只有 WebDAV 搜索行**

根因是**CSS 优先级冲突**（本次改造引入）：

```css
.tbs-online #engine-container { display: none; }          /* 旧规则：默认隐藏，特异性 (0,2,1) 含 ID */
.tbs-src-popover .custom-select { display: block; }        /* 我的规则：(0,2,0) → 输 */
```

旧规则只在 `.tbs-online.expanded` 时才放开，而 `.expanded` 是**在线输入框聚焦时**（`tbsExpandOnline()`）才加的类 —— 所以「先点搜索框」芯片才出现，「直接点音源」就是空浮层。修法：

```css
.tbs-src-popover #engine-container,
.tbs-src-popover #mf-plugin-container { display: block !important; flex: none; height: auto; }
```

**② 宽屏下切到「在线资源」时全局 ⋯ 菜单按钮消失**（既有 bug，非本次改造引入）

`updateSearchUI('在线资源')` 把菜单宿主交给 `refreshOnlineUI()`，后者会把 `#global-menu-1-wrapper` 追加到 `#menu-dropzone-lx` / `#menu-dropzone-wd`；而这两个容器所在的 `#online-toolbar-container` 在宽屏是 `display: none !important` → 菜单按钮被藏进隐藏容器。修法：在已有的 `refreshOnlineUI` 包装里，宽屏时把它收回 `#menu-dropzone-row1`（即宽屏工具栏右栏的那个 dropzone），窄屏逻辑不变。

**③ 关于「在当前网盘中极速检索...」文案**：这是**原有文案**（`#wd-search-input` 的 placeholder，自 2026-07-29 上游导入起就存在），不是新加的；浮层里的代理输入框沿用了同一句。含义：在**当前选中的 WebDAV 网盘（服务器）**内做快速检索（引擎的 `searchSong` 就在该网盘已缓存的曲库里按文件夹名 / 歌曲名匹配）。

### 3.11 歌单名与 (数量) 的截断优先级

**现象**：宽屏歌单栏被压缩时，名字被截成「所有歌…」，而 `(1750)` 始终完整显示。

**原因**（原作者设计，非 bug）：`utils.js` 的 `formatPlaylistText()` 把标签拼成一行三个 span，并写死了压缩策略：

```js
icon  → flex-shrink: 0                                     // 永不压缩
name  → overflow:hidden; text-overflow:ellipsis; flex-shrink:1; min-width:0   // 唯一可压缩 + 省略号
count → flex-shrink: 0; font-size:14px                     // 永不压缩
```

所以列一窄，可压缩的只有名字。

**改动**：在 `#playlist-val` 内改为「名字优先」——名字保留约 4.5 个字的最小宽度，空间不足时先压缩/裁掉 `(数量)`：

```css
#playlist-val > div > span:nth-child(2) { min-width: 4.5em !important; }   /* 名字 */
#playlist-val > div > span:nth-child(3) { flex-shrink: 1 !important; min-width: 0 !important; overflow: hidden !important; white-space: nowrap !important; }
```

（`formatPlaylistText` 里的 `flex-shrink:0` 是 inline 样式，必须用 `!important` 覆盖；结构固定为 span1=图标、span2=名字、span3=(数量)、其后可选 tags，所以用 `nth-child` 定位稳定。）

### 3.12 半宽屏仍挤在一行 → 同行判定改为"窗口下限 + 实测"（⛔ 已撤销，见 3.13）

用户反馈：全屏时工具栏位置正确，半宽屏时位置没有修正。

原因：原先只用 `WIDE_TOOLBAR_INLINE_MIN = 1100` 一个窗口阈值判断。半宽屏的实际宽度受显示器分辨率影响（2560 的一半是 1280，笔记本常见 1280–1440），都 ≥1100 → 仍然走"与 header 同行"，于是看起来"没修正"。

改为**两个条件缺一即回退两行**：

1. **窗口下限提高到 1440**：半宽屏 / 常见笔记本宽度一律两行，只有足够宽的窗口才与 header 同行；
2. **实测二次确认**：先生成同行布局，再量当前可见搜索框（本地模式量 `#search-input`，在线模式量 `#tbs-lx-input`）的宽度，`< 160px` 就立即退回两行 —— 这样能覆盖"塞得下但很挤"的情况，不再依赖纯猜宽度。

另外加了 `wideInlineBlockedAt` 记忆：在某个宽度实测太挤回退后，**同一宽度不再反复试排**，避免"试排 → 回退 → 再试排"与 `MutationObserver` 形成循环；窗口宽度变化后会重新判定。

### 3.13 方向修正：任何宽度都保持在 header 那一行

**用户澄清**：「全屏时新工具栏的位置是对的，半宽屏时显示位置未修正」——意思是**工具栏应始终保持在与 header 同一行**（即原来「本机 / 小爱音箱」所在那一行），而我 3.7 / 3.12 把它做成了「窗口变窄就退回第二行」，退回第二行恰恰就是用户所说的"未修正的旧位置"。方向反了。

**撤销与改法**：

1. 删除 `WIDE_TOOLBAR_INLINE_MIN` / `WIDE_TOOLBAR_SEARCH_MIN` 两个阈值、实测回退逻辑、`wideInlineBlockedAt` 记忆变量与 `resize` 重排监听；
2. CSS 门控由 `body.wide-toolbar-inline` 改为 `body.split-view-active`，即**只要在分栏里就把工具栏放在 header 右半栏**，`#playlist-row` 在分栏下整体隐藏（含 `player-open`，避免留一条空行）；
3. `--split-list-top` 统一为 `58px`（≥960 分支的那处 `115px` 也改掉）；
4. 宽度不足不再靠"换行"解决，而是靠**压缩**：搜索框 `flex: 1` 自行收窄；另加 `@media (max-width: 1099px)` 紧凑规则（歌单栏 `min-width: 96px`、开关与按钮内边距收紧、设备文字 `max-width: 84px`），优先保证搜索框有可用宽度。

> 教训：用户说"位置不对/未修正"时，先确认**他要的目标位置**，而不是自己推断"太挤就该换行"。

### 3.14 半宽屏输入框太小 → 聚焦时让出「所有歌曲」栏

**背景澄清（用户）**：所谓「半宽屏」= **平板（Pad）分屏**显示本 App（iPad / 安卓 Pad / Windows Pad 都算），约占全屏的 **2/3**；「全屏」= 完整宽屏；缩到 **1/3** 时跌破 768px 进入手机模式。也就是说半宽屏的实际宽度约 700–950px，右半栏只有 350–475px —— 工具栏里「本地/在线」开关、搜索框、搜歌/搜单、音源、歌单栏、设备挤在一起，搜索框被压到几乎看不见输入内容。

**改动**（采纳用户建议）：

1. **点搜索框时收起「所有歌曲」栏**：聚焦 `#tbs-lx-input`（在线）或 `#search-input`（本地）时，给 `body` 加 `.toolbar-search-focus`，CSS 隐藏 `.tbs-playlist` 及其后的分隔线；失焦即恢复。
   - 只点工具栏内的按钮不会触发恢复：`#tbs-online` 上的 `mousedown` 防夺焦逻辑会让输入框保持焦点，因此**不会在点击「搜歌/搜单/音源」的瞬间发生布局跳动**（否则按钮会在 mouseup 前移开，点击失效）。
   - 回到手机模式（非分栏）时主动清除该状态。
2. **搜索框设 `min-width: 80px`**：否则极窄时会被压成 0 宽 —— 点不到，也就无法触发上面的收起逻辑。

> 副作用（已知、可接受）：在 768–820px 且处于「在线」模式时，若输入框未聚焦，工具栏可能把「搜歌/搜单/音源」挤出可视区（`.tbs-online` 是 `overflow: hidden`）。点一下输入框即可让它们回来；回车同样能发起搜索。若这种宽度下仍嫌挤，下一步可把这三个按钮改成纯图标，或进一步隐藏设备栏。

### 3.15 半宽屏按钮标签精简（用户建议）※ 触发条件由 3.16 修正

用户建议：半宽屏下把「搜歌 / 搜单 / 音源」精简成「歌 / 单 / 源」，用文案换宽度。

**实现**：每个按钮放**两套标签**，由 CSS 切换（不写 JS、不动按钮逻辑）：

```html
<button class="tbs-lx-btn" id="tbs-lx-search-btn" title="搜索歌曲"><span class="lbl-long">搜歌</span><span class="lbl-short">歌</span></button>
```

```css
.tbs-lx-btn .lbl-short { display: none; }          /* 默认：搜歌 / 搜单 / 音源 ▾ */
@media (max-width: 1099px) {                        /* 半宽屏：歌 / 单 / 源 ▾ */
  .tbs-lx-btn .lbl-long { display: none; }
  .tbs-lx-btn .lbl-short { display: inline; }
}
```

- 给两个按钮补了 `title`（搜索歌曲 / 搜索歌单），精简后仍可悬停确认含义；
- 已确认 JS 从不读取这两个按钮的文字（只绑 click），因此改标签不影响任何逻辑；
- 约省 50px，叠加 3.14 的「聚焦收起歌单栏」（再省约 96px），搜索框在半宽屏聚焦后约有 100–170px 可用宽度。

**各宽度预算（在线模式，右半栏可用宽度）**：

| 窗口宽度 | 右半栏 | 未聚焦 | 聚焦（歌单栏让位） |
| --- | --- | --- | --- |
| 910（12.9" Pad 2/3） | ≈439 | 输入框 ≈77px | ≈173px ✅ |
| 787（11" Pad 2/3） | ≈377 | ≈15px（按钮可能被裁，输入框仍有 80px 下限可点） | ≈111px ✅ |
| 768（分栏下限） | ≈368 | ≈6px（同上） | ≈102px ✅ |

结论：**只要点一下搜索框，任何分栏宽度下都有可用输入宽度**；未聚焦时在 768–850 的「在线」模式仍偏挤，如需继续优化可把「源 ▾」改成纯图标，或聚焦时连设备栏一起收起。

### 3.16 标签精简改为「状态驱动」+ 半宽屏提示文字缩小

用户澄清两点，3.15 的实现不准确：

1. **精简标签只该出现在"还没点搜索框"的时候**：点开搜索框后歌单栏已经让位、空间充足，就应恢复完整文字（搜歌 / 搜单 / 音源 ▾）。
   - 改法：把 3.15 里"窄屏一律精简"的规则加上 `:not(.toolbar-search-focus)` 条件；
   - 因为**基础状态本来就是完整文字**（`.lbl-long` 默认 inline、`.lbl-short` 默认 `display:none`），所以只需写"未聚焦时"的覆盖规则，聚焦后自动回落到完整文字 —— 不需要再加一条反向规则。
2. **半宽屏下提示文字要小一档才协调**：给搜索框加
   ```css
   body.split-view-active .tbs-online .tbs-input::placeholder,
   body.split-view-active .tbs-online #search-input::placeholder { font-size: 12px; }
   ```
   只缩 **placeholder**（提示文字），**输入后的正文仍保持 14px** —— 与用户此前"字体不用变小"的要求一致。

**三态对照**：

| 宽度 / 状态 | 按钮文字 |
| --- | --- |
| 任意宽度，>1099 | 搜歌 / 搜单 / 音源 ▾ |
| ≤1099 且**未**聚焦搜索框 | 歌 / 单 / 源 ▾（省约 50px 给搜索框） |
| ≤1099 且**已**聚焦搜索框 | 搜歌 / 搜单 / 音源 ▾（歌单栏已让位，空间足够） |

### 3.17 搜索按钮风格 + 推送歌单更名

**① 「搜歌 / 搜单」改为搜索按钮风格**

**② MIoT 推送歌单更名：`iWebPlayer-S推送` → `iWP-S推送`**

只在 `static/miot.js`（3 处），并把旧名纳入匹配：

const PUSH_PLAYLIST_NAME = 'iWP-S推送';
const LEGACY_PUSH_PLAYLIST_NAMES = ['iWebPlayer-S推送'];
const isPushPlaylist = (pl) => !!pl && (pl.name === PUSH_PLAYLIST_NAME || LEGACY_PUSH_PLAYLIST_NAMES.indexOf(pl.name) !== -1);

复用查找（`_pushPlaylistId` 命中判断、重建前删除）都改走 `isPushPlaylist`，**升级后第一次推送会删掉旧的 `iWebPlayer-S推送` 并新建 `iWP-S推送`**，不会在音箱上留孤儿歌单。
